## 4. التواصل بين الواجهة والخادم (الـ API)

| البند | الاتفاق | مثال |
|---|---|---|
| شكل الروابط | أسماء جمع بالإنجليزي، تبدأ بـ `/api/` | `/api/students/` ، `/api/applications/12/` |
| أسماء الحقول | snake_case (نمط Django الافتراضي) | `student_id` ، `start_date` |
| التواريخ | سنة-شهر-يوم | `2026-10-01` |
| حالات الطلب | رموز إنجليزية ثابتة بقاعدة البيانات، والواجهة بتعرض الاسم العربي | انظر الجدول تحت |
| تسجيل الدخول | الخادم بيرجع توكن، والواجهة بترسله مع كل طلب | `Authorization: Bearer <token>` |
| الأخطاء | شكل Django REST Framework الافتراضي | `{"detail": "..."}` أو `{"email": ["..."]}` |
| القوائم الطويلة | صفحات (20 عنصر بالصفحة)، بالشكل الافتراضي | `{"count", "next", "previous", "results"}` |

### حالات الطلب

| الرمز | الاسم المعروض |
|---|---|
| `draft` | مسودة |
| `submitted` | مرسل |
| `under_review` | قيد المراجعة |
| `needs_changes` | بحاجة لتعديل |
| `accepted` | مقبول |
| `rejected` | مرفوض |
| `assigned` | تم التوزيع |

قبل كل وحدة (Module)، وفاء بتشارك قائمة الـ APIs الخاصة فيها (Swagger)، وحسين وعبد الله بيقدروا يشتغلوا على بيانات وهمية لحد ما تجهز.
